# GOALS.md

# Product Mission

Maximize career progress, income potential, and professional adaptability while minimizing unnecessary learning effort.

The platform exists to help users learn only what matters.

---

# Primary Objective

Optimize:

Career Progress Per Hour Invested

rather than:

Knowledge Acquired

---

# Core Principles

## 1. Outcome First

Learning is a means, not the goal.

Success is measured by:

* Jobs obtained
* Freelance revenue
* Consulting opportunities
* Products launched
* Portfolio quality
* Verified skills

---

## 2. Maximum Return, Minimum Effort

The platform should continuously seek:

* Faster paths
* Simpler paths
* Higher-leverage paths

while eliminating low-value learning.

---

## 3. Learn Only What Matters

Before recommending any topic, determine:

* Career value
* Income value
* Portfolio value
* Longevity
* Automation leverage

Topics with poor returns should be deprioritized.

---

## 4. Durable Knowledge First

Prioritize:

* APIs
* Automation
* Systems thinking
* Software architecture
* Workflow design
* Problem solving

before rapidly changing framework-specific knowledge.

---

## 5. Do Not Ignore High-Value Opportunities

If an emerging tool has:

* Strong demand
* Low learning effort
* High earning potential

the platform should recommend it.

---

## 6. Automation Before Complexity

Always prefer:

* Automation
* Reuse
* Existing solutions
* Composition

before custom engineering.

---

## 7. Verify Before Teaching

All educational content should:

* Reference primary sources
* Track versions
* Monitor deprecations
* Surface uncertainty

---

## 8. Build Before Memorize

Practical application should occur as early as possible.

Users should build, modify, and troubleshoot before extensive theoretical study.

---

## 9. Competency Over Completion

Progress is measured by capability rather than lesson completion.

Required evidence:

* Can build
* Can modify
* Can explain
* Can troubleshoot

---

## 10. User Agency

The platform must support two modes.

### Roadmap Mode

The platform determines the highest-value next step.

### Exploration Mode

The user requests a topic.

Examples:

* Learn Hermes
* Learn MCP
* Learn Docker
* Learn FastAPI

The platform evaluates the request and generates the optimal learning path.

---

# Learning Decision Framework

Every recommendation should evaluate:

Expected Career Return

Expected Income Return

Expected Longevity

Expected Automation Leverage

Expected Portfolio Value

Expected Market Demand

versus

Learning Time

Maintenance Cost

Complexity

Opportunity Cost

# Non-Goals

The platform should not become:

* A generic LMS
* A course marketplace
* A certification platform
* A social network
* A discussion forum
* A content library without guidance

---

# Feature Acceptance Test

Before adding a feature, answer:

1. Does it improve career outcomes?
2. Does it improve income potential?
3. Does it reduce learning effort?
4. Does it improve decision quality?
5. Does it improve adaptability?
6. Can it be replaced with something simpler?

If most answers are "No", the feature should not be added.

---

# Ultimate Product Test

At any moment the platform should be able to answer:

* What should I learn next?
* Why should I learn it?
* Why now?
* What can I earn from it?
* How long will it remain useful?
* What can I safely ignore?
* What should I automate instead of learn?
* What is my fastest path to my goal?

If the platform cannot answer these questions, it is failing its mission.
